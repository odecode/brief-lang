# Float formatting return on wasm32 — 2026-11-02

Reproducer: the recommender browser protocol accepts a score 4.5 and its card displays 0; a literal 4.5 cast to String also displays 0. Native Print# of 4.5 as String prints 4.5. The formatter's target-width `Int` initially looked suspicious, so an explicit `Int64` variant was tested. That variant introduced standard-library contract-proof failures. Restoring the original formatter while retaining the backend correction still renders `4.5 / 5 predicted`, so the width hypothesis was refuted and the formatter change was removed.

The decisive compiler bug: wasm IR for `frac_all_digits` called `frac_digit_loop` then returned literal zero. A recursive `term` in an earlier `when` set `tail_loop_backedge`, and guarded-statement emission left that flag set on the later fallthrough. The later terminal call therefore skipped its return, and the backend inserted a zero fallback. Clear the backedge flag at the guarded merge, as the false continuation has not taken the recursive backedge. Add a wasm IR regression with a recursive guarded term followed by a terminal call. This is general tail-loop state handling, not a recommender or score special case.

Verification: compile native and browser targets; check literal and decoded 4.5 browser formatting, full pending-peer browser flow, native output, and an isolated wasm fixture for normal and fractional values. The browser fixture displayed `4.5 / 5 predicted` with only the backend correction. The isolated import and package tests that the width variant broke passed after its removal. Run the required compiler test suite only after the app/browser check; known SPIR-V environment failures remain accepted.
