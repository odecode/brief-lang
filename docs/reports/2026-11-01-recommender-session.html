Application changes

App · frontend

Bound selection work to the visible movie cards

examples/recommender/app.rbv now updates the existing 12 visible movie cards when a movie is chosen. It reads each card's existing title and preserves its rating and identity while changing the selected state.

  • Avoids scanning the full catalogue and rebuilding the profile overlay on every choice.
  • Does not issue a selection request to the backend; selection remains immediate and local.
App · frontend contract

Corrected logout confirmation completion condition

The pending-save logout transaction now requires authentication and confirmation on entry, then requires the signed-out state on completion. Logout clears the confirmation flag, so the previous postcondition described a state the action itself removed.

App · build and source integration

Aligned the launch path with the app being tested

The user launches the compiler checkout's examples/recommender/run-demo.sh. The bounded selection update and browser regression coverage were applied to that checkout as well as the separate app checkout, avoiding a rebuild of one copy while serving another.

The compiler-checkout demo was rebuilt and served at http://localhost:8081; its backend runs on port 8080.

App · stdlib compatibility

Updated recommender vector type names in the separate app checkout

Migrated the six recommender library files from Vector/Matrix to the stdlib's FloatVector/FloatMatrix names. Its launcher also passes explicit compiler configuration and stdlib paths.

Compiler changes

Compiler · web code generation

Stopped inline collection reads from publishing partial page state

Inline member bodies now carry scoped context that suppresses browser DOM flushes. The surrounding transaction retains its identity and publishes its completed state once. This is general compiler behavior: it does not recognize recommender names or collection types.

Generated selection went from 14 flushes per click to one. The duplicate publication on the bare transaction term was also removed: publication and cleanup now happen only after the term's postcondition succeeds.

Compiler · LLVM register emission

Kept callable transaction registers unique

Moving transaction prologue instructions into the function body exposed a counter reset after entry locals were allocated. The reset now occurs before any function instructions, keeping entry allocations and body values in one monotonic register namespace.

Compiler · enum layout

Used resolved object sizes for enum payload planning

Enum planning now consumes object byte sizes from the type universe, matching the layout used by struct emission. Unknown sizes do not qualify for inline storage. Finite object payload eligibility no longer changes with enum nesting depth, keeping nested and standalone representations ABI-compatible.

Compiler · enum field typing

Scoped enum constructor context to each field

Struct field emission now uses the field's declared enum type and restores the prior context afterward. This prevents an unrelated outer return enum from determining a nested field's representation.

Compiler · object lifetime

Made extracted inline enum objects owned

Matching an inline object payload previously returned a pointer into a temporary stack image. If the value escaped, it could point into a dead stack frame. Bound object payloads are now copied to owned storage unless a non-retaining projection is proved.

Compiler · callable transaction layout

Moved transaction local allocation into the function body

Callable transaction stack allocations are emitted after the function entry label and before parameter binding, instead of at module scope where LLVM rejects them.
