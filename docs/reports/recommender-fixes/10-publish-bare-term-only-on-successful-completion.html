Publish bare term only on successful completion

Intended behavior and failure

A bare term must publish and perform exit cleanup only when its completion postcondition succeeds. The old common Term path published before that decision, while the successful bare-term stop path published again.

Reading the code

val is an Option containing the value of a value-returning term, if present. is_some() distinguishes it from a bare term. The corrected common path handles value terms only; the existing emit_bare_term_stop path owns successful bare-term publication and cleanup. This aligns observable page updates with the transaction’s completion condition.

Why the correction works and how it was checked

After inline-member suppression, selection still flushed twice. This change brought it to one and also prevents premature cleanup/publication when the bare-term postcondition is false. All nine focused bare-term checks passed.
