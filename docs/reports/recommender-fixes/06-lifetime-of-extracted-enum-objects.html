Compiler · Fix 06

Lifetime of extracted enum objects

Intended behavior and failure

Extracting an object from an enum must yield a value whose storage remains valid for its use. Previously extraction returned an address inside the enum image, which could live on a stack frame that subsequently returned.

Reading the code

The Rust code here writes LLVM text with writeln!, rather than directly allocating application objects in Rust. inttoptr converts an integer handle to a pointer. getelementptr i64 ..., 1 skips the eight-byte enum tag. The old code converted that interior address back to a handle. The new helper emits malloc and memcpy to copy the object’s byte image into owned storage, then returns its handle.

Why the correction works and how it was checked

The native server reached startup and then crashed freeing an invalid buffer handle after the containing stack frame died. The owned image fixes the outer storage lifetime; it is a byte-image copy, not a recursive deep clone. The lifetime repro fails with old emission at O0 and passes with the fix. Old optimized code happened to pass, making the unoptimized gate important.
