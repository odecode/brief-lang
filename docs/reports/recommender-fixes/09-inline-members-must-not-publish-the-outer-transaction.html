Compiler · Fix 09

Inline members must not publish the outer transaction

Intended behavior and failure

An inlined collection member returns to its caller; that return is not completion of the caller’s transaction. The old emission kept the outer transaction name but had no context distinguishing an inline member return from an outer publication boundary.

Reading the code

mem::replace sets in_inline_member to true and saves the previous Boolean. After emitting the member body, restoring the saved value supports nested inline calls. emit_web_flush_batch now returns early when this flag is true. Keeping txn_name intact preserves the analysis proofs associated with the surrounding transaction.

Why the correction works and how it was checked

Twelve indexed card reads triggered repeated page reconciliation. Scoped suppression reduced 14 flushes to two; the separate bare-term correction removed the last duplicate. A compiler regression checks publication count and the generated-browser fixture checks actual flushes.
