Visible-page selection

Intended behavior and failure

Choosing a movie should change the selected ID, title and card highlight. The old handler also calculated the current rating overlay and refreshed the catalogue page. Those operations are useful when ratings or filters change, but selection already has the needed information in the visible cards.

Reading the code

In Briev, txn declares a transaction. The first bracket is its precondition and the second is its completion postcondition. let declares a local; List is a typed list; .^Length reads collection length; <- appends; when executes a guarded block. The old three calls looked small but delegated catalogue and profile work. The new loop copies the existing cards, preserving rating and identity while setting selected from an ID comparison.

Why the correction works and how it was checked

The page contains 12 cards, so work is bounded by that page instead of the 1,682-movie catalogue and rating overlay. This assumes selection originates on the visible page, as the Choose buttons do. Off-page selection would need another title lookup path. Browser checks confirmed title/highlight updates, unchanged ratings/page, and no selection network request.
