Compiler · Fix 07

Transaction allocations inside the function

Intended behavior and failure

Local stack allocations belong inside the LLVM function that uses them. The old callable-transaction emitter wrote its body prologue before the function header.

Reading the code

emit_body_prologue discovers and emits local storage needed by the transaction body. writeln! appends LLVM instructions to the output string. PrologueOpts::default() constructs default options. The call is moved after the emitted entry label, but remains before parameter binding so the existing binding order is preserved.

Why the correction works and how it was checked

A reassigned local caused alloca to appear at module scope and LLVM rejected the app. A callable-local regression checks allocation placement; the isolated repro and app frontend compiled successfully.
