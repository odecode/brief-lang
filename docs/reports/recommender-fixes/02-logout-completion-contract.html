Reading the code

The two bracket expressions following txn are entry and completion conditions. && means both conditions must hold; ! negates a Boolean. term requests completion under the transaction contract. Previously premature browser publication concealed the inconsistent postcondition. Once publication was corrected, the browser regression exposed it.

Why the correction works and how it was checked

The entry condition now requires authenticated && logout_confirmation and completion requires !authenticated. The pending-peer browser test covers confirmed logout and cancellation.
