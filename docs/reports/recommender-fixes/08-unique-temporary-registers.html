Compiler · Fix 08

Unique temporary registers

Intended behavior and failure

Every LLVM SSA temporary name must be defined only once inside a function. Resetting the temporary counter after the entry prologue could reuse names allocated by that prologue.

Reading the code

self.fun is the current function’s compiler state; assigning txn_counter = 0 resets its name generator. The old reset was near in_callable_txn setup, after local allocations. The fix moves it to the very beginning of emit_callable_txn, before either entry or body emission.

Why the correction works and how it was checked

A changed emission sequence exposed two definitions of %t82: an alloca and a later pointer calculation. The function now uses a single increasing name sequence. The callable regression checks duplicate SSA definitions, and LLVM accepted the rebuilt output.
