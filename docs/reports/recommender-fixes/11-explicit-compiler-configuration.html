Explicit compiler configuration

Intended behavior and failure

Building the external app should use the same compiler configuration and stdlib as building from the compiler checkout. Relying on the working directory or executable location to discover configuration failed for cached binaries.

Reading the code

This file is Bash: ${NAME:-fallback} uses a fallback when an environment variable is unset or empty; [[ -d path ]] checks a directory; quoted variables prevent whitespace splitting. The new BRIEV_CONFIG_DIR override, sibling-config discovery and --config-dir arguments make the two build commands explicit. The stdlib root is lib, containing std, rather than lib/std.

Why the correction works and how it was checked

The external build had reported a Float/Int mismatch without the intended configuration. Explicit paths allowed frontend and server builds. This is launcher integration, not a change to the compiler’s type rules.
